# Optional exact-CAD to volume-mesh bridge

This development integration preserves the existing `neurocad` command and adds
one companion: `neurocad-mesh`. It combines the exact-CAD expansion already on
main with the verified optional Gmsh adapter from development PRs #69 and #70.
It does not require either native kernel for the default installation.

## Run the shipped example from this branch

Use Python 3.12 for this combined-backend example. On Ubuntu, install the native
Gmsh runtime prerequisite `libglu1-mesa` first. In a fresh virtual environment:

```sh
python -m pip install -e '.[exact-build123d,mesh-gmsh]'
neurocad feature build docs/examples/cad_mesh_box.ncad2.json --output-dir cad-example
neurocad-mesh step cad-example/design.step --output-dir mesh-example --max-size 3
```

Both output directories must be new. The CAD bundle contains `design.step` and
`build-receipt.json`; the mesh bundle contains `design.msh` and
`meshing-receipt.json`. The original CAD bundle remains unchanged. The mesh
receipt's `source_step_sha256` must equal the CAD receipt's `step_sha256`.
The companion is also callable as `python -m core.mesh_cli`.

The `neurocad feature`, validation, requirements and other existing commands are
unchanged. This integration does not add `neurocad mesh` to the main command:
the companion avoids rewriting the shared CLI while providing the same optional
STEP-to-mesh operation. Files already generated by the earlier branch can be
passed to `neurocad-mesh step` without conversion.

## Discovery and verification

`neurocad integrations` continues to discover every existing integration. Gmsh's
standalone executable is still reported separately. Only detection of the Python
module enables the adapter capability; executable discovery alone is insufficient.
Module discovery is not proof of native library availability or a successful run.

The copied adapter rejects invalid inputs and existing destinations, snapshots
the source it hashes, verifies exported node identities/coordinates, 2-D/3-D
connectivity and physical-group membership after reopening MSH, and publishes
using native no-replace directory operations. Its existing verification limits
and floating-point tolerances are unchanged.

A separate read-only, exact-head CI workflow imports both pinned native backends
before testing a box, a holed plate, a filleted box and the two-command pipeline.
It additionally executes the installed console scripts on the shipped example
and retains actual STEP/MSH fixtures and test results, including failures.
The normal full CI and the exact-CAD native lane are retained unchanged.

containment. No research outcomes or frozen scientific protocols are changed.
